# /enforce_spec

当用户输入此指令，或者在进入 **MVP 模式** 准备开始编写代码前，你必须**首先**执行此命令所定义的检查流程。

## 目的
在执行任何核心代码变更前，强制检查 `docs/superpowers/specs/` 目录下是否有近期的 Spec 或 Plan 沉淀。如果未发现近期沉淀，则**强制中断当前流程**并自动执行沉淀。

## 执行流程（你必须按顺序严格执行）

1. **扫描规范目录**：
   - 检查 `docs/superpowers/specs/` 目录是否存在。
   - 扫描该目录下所有的 Markdown (`.md`) 文件。
   
2. **检查更新时间**：
   - 找到最近修改时间最新的一个 `.md` 规范文件。
   - 检查该文件的最后修改时间距离当前时间是否**超过了 2 小时**。

3. **执行物理拦截与自动修正**：
   - **如果目录不存在、没有找到文件，或者最新文件距今已超过 2 小时**：
     - 判定为：**本次讨论的方案尚未沉淀为规范文档**。
     - **强制动作**：
       1. **立即停止**一切编写业务代码、拆解子任务或执行后续步骤的行为。
       2. **主动调用文件写入工具**，将刚才与用户讨论的技术设计、优化方案或新功能需求，梳理成标准的 Markdown 格式。
       3. 将这份新的 Spec 和开发 Plan 保存到 `docs/superpowers/specs/` 目录下（文件命名规范参考项目已有文件，如 `YYYY-MM-DD-xxx.md`）。
       4. 在文件创建并保存成功后，向用户汇报已完成 Spec 沉淀，并询问是否可以基于该 Spec 开始正式编码。
   
   - **如果最新文件距今在 2 小时以内**：
     - 判定为：**规范检查通过**。
     - 向用户简短汇报：“已检测到近期的规范沉淀 (`文件名`)，规范检查通过。”
     - 继续执行后续的编码或计划执行流程。

## 触发条件
- 用户手动输入 `/enforce_spec`。
- 在 `SUPERPOWERS-MVP.md` 模式下，完成“设计先行”讨论并获得用户批准后，**准备进入下一步写代码或制定实施计划之前**，由系统规则强制隐式调用本命令。
